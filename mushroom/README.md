# 菌野 · 中国野生菌探索指南

基于 FastAPI + Jinja2 的野生菌科普站。前台默认端口 8000，独立内容管理端默认端口 8002。前端资源本地提供，无需 Node 构建或外部 CDN。

## 启动

```powershell
cd D:\work\AI\webs\mushroom
python -m pip install -r requirements.txt
python main.py --host 127.0.0.1 --port 8000
```

在另一个终端启动管理端：

```powershell
python manage.py --host 127.0.0.1 --port 8002
```

访问 `http://127.0.0.1:8000/` 浏览网站，访问 `http://127.0.0.1:8002/login` 进入管理端。首次需在服务器本机设置至少 12 位的管理员密码。密码以 PBKDF2 哈希存储，不设置通用默认密码；会话持续 8 小时。

端口占用时，两个启动脚本会在随后 10 个端口中寻找可用端口，请以控制台打印的实际地址为准。生产环境建议使用下方固定端口命令。

## 运营配置

后台“内容工作台”提供以下表单：

- **站点设置**：网站名称（默认“菌野”）、副标题、简介、合作联系方式、ICP备案号、前台地址、页脚说明。
- **首页轮播**：新增、移除、排序、启停；编辑主副标题、图片或视频、视频封面与按钮链接。支持上传 JPG、PNG、WebP、GIF、MP4、WebM，单文件最大 80MB。
- **游戏管理**：封面、介绍、分类、引擎、游玩入口、内嵌/新窗口模式与上下架；支持上传 Web 游戏 ZIP 包。
- **安全科普**：标题、分类、摘要、正文、封面、参考来源与发布开关；正文以空行分段，按普通文本渲染。
- **广告管理**：图片、介绍、跳转链接、投放页面与开关。广告明确标注“广告”，未配置时不占空白广告位。当前为直接广告素材投放，不包含广告联盟 SDK 或结算统计。
- **菌子资料**：保留原有资料编辑、主图和扩展图片管理。图鉴按名称或拉丁名搜索，分类和分页均由后台数据驱动。

修改后点击“保存并生效”，前台刷新即可读取最新配置，无需重启前台。内容工作台有版本冲突检查，避免两个编辑者直接覆盖彼此的修改。管理服务运行单个 worker。

## 游戏接入

网站自带两款可玩的 HTML5 游戏：**林间寻菌**（记忆翻牌）和 **菌野知识挑战**（安全常识）。

1. 在 Cocos、Unity、Three.js 或其他工具导出浏览器可玩的 Web 版本。
2. 将导出目录压成 ZIP，必须包含 `index.html`，保留所有相对目录。最大 150MB、解压后 600MB、10000 个文件。
3. 在“游戏管理”新增卡片，填写仅含小写字母、数字和短横线的唯一标识，例如 `forest-match-v1`。
4. 点击“上传 Web 游戏 ZIP”，入口地址自动回填；上传封面、填写介绍、选择引擎和分类。
5. 勾选“上架展示”，点击“保存并生效”。游戏大厅将出现卡片，点击可游玩并全屏。

每次上传更新版本请用新目录标识，避免覆盖正在运行的资源。旧目录可在确认无引用后手工归档。大于上传上限的游戏可部署到自有静态站或 CDN，并填写完整 HTTPS 入口地址。

Unity 建议关闭多线程，使用未压缩构建或启用 Decompression Fallback。站点为 `.gz`/`.br` 文件设置 Content-Encoding，并为 `.wasm` 提供正确类型，但实际构建仍需验证浏览器和设备兼容性。依赖 SharedArrayBuffer 的多线程构建需要额外配置跨源隔离及相关资源响应头。第三方游戏若禁止 iframe 嵌入，使用“新窗口游玩”。

## 数据与备份

- `data/mushroom.csv`：现有菌子资料，保留原始字段与数据。
- `data/image/`、`data/image_ex/`：现有菌子主图及扩展图。
- `data/banner/`：原有视频素材。
- `mushroom_app/content/defaults.json`：初始站点配置。
- `data/site.json`：第一次在内容工作台保存后生成的实际配置；使用原子替换写入。
- `data/uploads/`：管理端上传的图片与视频。
- `games/`：本地游戏资源；通过 `/play/` 提供访问。
- `data/.admin-auth.json`：管理员密码哈希和会话密钥，不可公开访问或提交到版本库。

备份完整 `data/` 与 `games/`；后台“导出配置”仅导出配置 JSON，不包含媒体。恢复配置时停止管理端，将导出的 JSON 放回 `data/site.json` 后启动；不需要改变前台代码。恢复图片与游戏时保持原目录路径。

## 生产部署

代码已经具备前后台独立运行和内容配置能力。正式上线需将项目部署到服务器，配置域名与 HTTPS，并将站点设置中的前台地址改为实际域名；现有素材版权与图鉴资料准确性应由运营方确认。

```text
python -m uvicorn main:app --host 127.0.0.1 --port 8000
python -m uvicorn manage:app --host 127.0.0.1 --port 8002 --workers 1
```

推荐由 Nginx/Caddy 等代理提供 HTTPS 和进程守护服务保持应用运行。前台域名指向 8000，管理端仅向获准人员开放。上传请求体上限至少配置为 160MB；应转发正确的 Host、X-Forwarded-Proto 等信息，并只信任实际反向代理地址。本站的会话 Cookie 在 HTTPS 下自动启用 Secure。

图鉴是观察与科普工具，当前没有接入图片自动识别模型。现有数据库的个别地方名、毒性和食用描述仍需要专业审核；前台已明确标注资料性质，游戏不做图片食用判断。

## 模块职责

- `mushroom_app/content/models.py`：配置 DTO、字段和 URL 校验。
- `mushroom_app/content/services.py`：发布筛选、配置保存及版本冲突规则。
- `mushroom_app/content/repositories.py`：配置和媒体持久化，原子文件写入。
- `mushroom_app/content/uploads.py`：媒体类型与游戏包校验规则，调用 repository 保存资源。
- `mushroom_app/content/admin_routes.py`：管理页面及 API 入参处理。
- `mushroom_app/admin/auth.py`、`auth_repository.py`、`access_routes.py`：登录校验、凭据存储和路由。
- `mushroom_app/web_assets.py`：静态资源挂载和 Web 游戏压缩响应类型。

基础验证包括页面访问、图鉴搜索与分类、两款游戏、后台登录及退出、配置即时生效、版本冲突、非法链接、跨站写入、上传格式与 ZIP 路径检查。首屏图片来自项目原有奶浆菌照片；默认游戏封面是本地 SVG 插画。
